# デザイン品質の検証

## 自動検証

実行:

```sh
node scripts/design/generate-tokens.mjs --check
node scripts/design/check-design.mjs --report
node --test scripts/design/design.test.mjs
```

初回実行: 2026-10-14 JST。
結果: 24 組の色コントラスト、生成ソースの一致、5 件の Node テストが成功。
主文の最小コントラスト 13.22:1、補足 5.32:1、アクセント 5.74:1、エラー文 6.05:1。
数値は不透明な指定色同士についての結果で、ネイティブ Liquid Glass 上の合成結果を計測した値ではありません。

`check-design.mjs` は `apps/ios` 内の Swift ファイルを調べ、DesignSystem と Tests を除く機能実装を対象とします。
次を検出します。

- 直接指定した RGB / hex / 名前付きの色。
- 機能側の `.font(...)`。
- 独自の material、glassEffect、blur。
- ナビゲーション背景・配色の上書き。
- 直書きの角半径、padding、stack spacing、アニメーション。
- Dynamic Type の clamp。
- WebView などによるネイティブガラスの代用。

標準の Button、Picker、Form、Menu、NavigationStack、TabView、意味トークンの利用は許可します。
例外には対象ファイル、規則、具体的な理由、ADR が必要です。
不要になった例外もエラーにします。

### 検査の限界

これは Swift コンパイラや AST ベースの完全なアーキテクチャ検査ではありません。
複雑な式や別名で禁止値を隠すこと、読書範囲の意味を誤ること、情報を詰め込みすぎることまでは保証しません。
UI レビューを置き換えず、意図しない簡単な逸脱を早期に止める役割です。
コメント除去や正規表現は Swift のすべての文字列構文を解釈しません。誤検出があれば局所的な検査改善を行い、全体を無効化しません。

## 視覚レビューの観点

1. 正本を見てから、同じ範囲の Light / Dark を比較します。
2. 面の階層、暖色の量、書名と範囲の主役性を確認します。
3. 機能追加前後で最初に目に入る内容が変わっていないか比較します。
4. 各アクセシビリティ設定を一つずつ、最後に組合せでも確認します。
5. 実施した端末、OS、設定、結果、残った問題を追記します。
