# Bible Companion デザインガイドライン

版: 1.0 / 2026-10-14（日本時間）

**静かな黒と白の面に、読むための順序をつくる。操作は iOS に委ねる。**

この文書と `tokens.json`、`apps/ios/Sources/DesignSystem` が、機能画面より先に参照する設計契約です。
新しい機能のために画面全体の材質や情報の優先順位を変えません。

## 1. 正本と判断の優先順位

1. ユーザーの指定したエアコン操作 UI のスクリーンショット `IMG_4272.png` を視覚的な正本とします。
   Library ID: `libfile_57e195904aa48191a90623a443255b57`。
   実際に確認した対象は、投稿アプリの黒い外枠ではなく、中央の黒い操作パネルです。
2. 承認された「立体の聖書 ライト／ダーク」案から、白い物体と黒い面、抑えた暖色の金属感、光と縁の繊細さを引き継ぎます。
   ユーザーの評価は「質感超いいね モデルはなくてもいいただ質感かなり理想」です。
   立体モデル、回転操作、常設の本のオブジェクトは必須要件ではありません。
3. 操作とアクセシビリティは、現行の Apple Human Interface Guidelines と iOS の標準挙動に従います。
4. 機能ごとの判断は、このガイドと設計 ADR に従います。

正本は「何を大切にするか」の判断資料です。
第三者の画像、アカウント画像、ロゴ、3D 資産を製品や公開サイトへ転載する許可を意味しません。
参照画像そのものはリポジトリへ複製していません。

## 2. 正本から引き継ぐもの

- 大きな一枚の落ち着いた面と、控えめな内側の面。細かなカードを無制限に積み上げません。
- 明るい文字による明快な主役。薄すぎる灰色や金色で本文を飾りません。
- 輪郭、陰影、余白による奥行き。背景全面のグラデーションや疑似ガラスで立体感を代用しません。
- 暖かみのある金属色は、選択や出典への小さな手がかりに使います。
- 機能が増えても、最初に目に入るものは「書名と選択範囲」「読む内容」です。

ライトモードは反転フィルターではありません。
やや温かい白の読書面と濃い文字を使い、同じ階層を別の明度で維持します。

## 3. 変更してはいけない約束

### 読む面と操作する層を分ける

本文、要約、解説、人物説明、出典は不透明な内容層です。
Liquid Glass は iOS 26 の標準 NavigationStack、TabView、toolbar、sheet などに任せます。
独自のガラス製タブバー、HTML の blur、半透明カードの多重重ねは実装しません。
標準部品の上に独自背景を置いて、システムの材質やスクロール端効果を隠しません。

### 範囲が変わらないことを視覚でも保証する

- 単節: 「ヨハネ 3:16」「1節」と示します。
- 複数節: 「ヨハネ 3:16–18」「3節」と示します。
- 章またぎ: 「使徒 18:24–19:7」「12節」と示し、章ごとに勝手に分割しません。
- 上限、下限、選択全体という意味を、色だけに依存せず言葉で示します。
- 表示タブや質問画面へ移っても同じ範囲を保ちます。
- 補助情報で範囲を越える場合は、利用者の明示操作と説明が必要です。

### 本文と生成された説明を混同しない

聖句本文、範囲の要約、AI 解説、歴史的資料を別のラベルで明示します。
本文の配信が許可されていない場合は、引用元を示し、本文らしい架空の文章で埋めません。
未取得の絵画や地図、人物像を「見つかった資料」として表示しません。

### 設定を読書の主役にしない

AI モデルの選択は「設定」に置きます。
読書ヘッダーにモデル切替や技術的なステータスを常設しません。
接続エラーなど現在の読書を妨げる情報だけ、その場で具体的に示します。

## 4. 色、形、余白、文字

色と寸法の機械可読な正本は `tokens.json` です。
Swift は生成スクリプトから作り、機能画面では数値や色を直書きしません。

| 意味 | Light | Dark | 用途 |
|---|---|---|---|
| canvas | #F7F7F3 | #101210 | 全体の読書面 |
| surface | #FFFFFF | #191B18 | 関連情報のまとまり |
| inset | #ECEDE7 | #252822 | 範囲のバッジなど |
| textPrimary | #21251F | #F2F3EC | 本文と見出し |
| textSecondary | #5D6257 | #B6BBAE | 補足、出典、状態 |
| accent | #685A36 | #C6BA96 | 選択、意味のあるリンク |
| border | #CBCFC2 | #434A3E | 装飾的な境界 |
| danger | #A02F32 | #F1A5A5 | エラー。アイコンと文章を併記 |

主文はすべての内容面で 7:1 以上、補足・アクセント・エラー文は 4.5:1 以上をテストします。
初版の最小値は主文 13.22:1、補足 5.32:1 です。
装飾的な境界色を単独の操作可否や選択の手がかりにしません。
Increase Contrast では共通コンポーネントの補足文字と境界を主文色に置き換えます。

余白は 4 / 8 / 12 / 16 / 24 / 32 pt、ページ左右は 20 pt。
内容面の角は 24 pt、内側は 16 pt、バッジは 8 pt。
操作部品の角やサイズは OS の標準を優先します。
読書列は最大 680 pt。狭い幅や大きな文字では縦に流れます。

文字はシステム書体を使います。
`title` は largeTitle、`heading` は title2、`verseReference` は title、`body` は body、`caption` は subheadline に対応します。
大きな数字も画像化しません。
固定ポイント数、本文への minimumScaleFactor、Dynamic Type の上限設定を避けます。
長い日本語、英語、URL を想定し、テキストを含む箱の高さを固定しません。

## 5. 画面の順序

### 読書

1. ネイティブのナビゲーションと必要最小限の操作。
2. 書名、節範囲、選択全体の説明。
3. 読書範囲の要約。展開前も要約だと明示。
4. 解説・地図・人物・絵画の切替。通常サイズでは標準 Picker、大きな文字では Menu などに退避。
5. 選択した内容と出典。
6. 「この範囲について質問」。同じ範囲を保持してネイティブ sheet へ。

「読書」「履歴」「設定」のアプリ移動と、読書内の内容切替は同じ部品に混ぜません。
画面の下へ操作を固定するときは安全領域を尊重し、本文末尾やキーボードを隠しません。

### 履歴

時系列の標準 List が基本です。
書名・範囲・日時で識別し、再開すると保存された範囲と同じ読書へ戻します。
写真、バッジ、統計などを追加して履歴をダッシュボード化しません。

### 設定

標準 Form と Section を使います。
モデル、表示、接続などを目的別にまとめ、選択結果と保存状態を区別します。
値の説明は具体的にし、保存前に成功の触覚を鳴らしません。

## 6. 状態も同じデザインで扱う

- Loading: 範囲を残し、標準 ProgressView と短い説明。偽の進捗率は使いません。
- Empty: 「この範囲の資料はありません」。中身のない美しいカードを作りません。
- Error: 失敗した操作と次の一手を明示。現在の範囲を消しません。
- Offline: 通信が必要な箇所だけ説明し、読める内容を維持します。
- Unsupported: 共有された参照を解釈できない理由と、修正できる入力を残します。
- Success: 保存や変更が実際に確定した時だけ控えめに知らせます。

## 7. 動き、触覚、アクセシビリティ

標準のスクロール、戻る操作、シートの閉じ方を尊重します。
遷移中でも操作を止めず、閉じた画面は開いた関係がわかるように戻します。
独自のスクロール物理やドラッグ認識は必要性が証明されるまで追加しません。

ローカルな状態変更には共通の減衰した動きだけを使います。
Reduce Motion では共通アニメーションを止め、読み順とフィードバックを保ちます。
内容面は元から不透明で、Reduce Transparency に左右されません。
ナビゲーションはシステム設定への自動適応を妨げず、実機で確認します。
触覚は明示的な選択と確定した保存に限り、生成文の一文字ごと、スクロール、単なる読込完了には使いません。

すべての操作に名前があり、アイコンのみの操作には accessibilityLabel を与えます。
見出しは VoiceOver の見出しとして辿れるようにし、範囲と状態は自然な文として読めるようにします。
少なくとも 44×44 pt の操作領域を確保し、色だけで選択・警告・成否を伝えません。
大きな文字では横並びを縦並びまたは標準 Menu へ変更し、内容を切り捨てません。

## 8. 許可される拡張

新しい解説、出典、地図、人物の情報は既存の内容パターンへ追加できます。
共通コンポーネントが不足する場合は、先に意味と利用範囲を設計して DesignSystem に追加します。
任意の立体表現は、読書を圧迫せず、消しても機能・意味が失われず、静止代替がある場合にのみ検討できます。
3D を実装すること自体を完成条件にはしません。

新しい色や材質、ナビゲーション構造が必要なら、ADR で理由・既存部品では足りない点・影響・検証方法を記録します。
「この機能だけ特別」は理由になりません。
例外は `exceptions.json` にファイル、規則、理由、ADR を明示し、不要になったら削除します。
現在の例外はありません。

## 9. 機能追加時のチェックリスト

- [ ] 正本の黒白の面、抑えた金属色、余白の階層を保ったか。
- [ ] 最初に読めるのは書名・範囲・内容か。モデル設定が割り込んでいないか。
- [ ] 単節、複数節、章またぎで同じ範囲を保持しているか。
- [ ] 本文、要約、生成説明、外部資料を区別したか。
- [ ] 新規画面はトークンと共通コンポーネントを使っているか。
- [ ] Liquid Glass は標準操作層に留まり、読書カードへ増殖していないか。
- [ ] Light / Dark / Increase Contrast / Reduce Transparency / Reduce Motion を確認したか。
- [ ] 最大 Dynamic Type、狭い幅、横画面、長い日本語、VoiceOver を確認したか。
- [ ] 読込、空、失敗、再試行、キャンセル、戻る、連続タップでも範囲を失わないか。
- [ ] 自動チェックが通り、未実施の実機検証を完了済みと書いていないか。
