# デザイン ADR

## ADR-001: 正本は黒い操作パネルの質感と階層

決定日: 2026-10-14 JST / 状態: 採用

ユーザー指定のスクリーンショットを正本にし、黒い一枚面、内側の落ち着いた面、抑えた暖色、明快な文字を抽出します。
エアコン、温度計、トグルの数や配置、SNS の周辺 UI は聖書アプリの要件ではありません。
承認された聖書案は質感の翻案として扱い、3D モデルの採用を義務づけません。

結果: 新機能は同じ読み順と材質へ収めます。見た目を合わせるために無関係な操作部品を増やしません。
検証: 正本との目視比較、Light / Dark の比較、読書の主役が変わらないこと。

## ADR-002: Liquid Glass はネイティブ操作層へ限定

決定日: 2026-10-14 JST / 状態: 採用

iOS 26 の標準ナビゲーション、ツールバー、タブ、シートを使います。
本文や解説カードは不透明にし、ガラス近似の WebView や独自ぼかしを製品の実装に使いません。
Apple の Materials と Adopting Liquid Glass の内容層／操作層の区別を優先します。
ユーザー指定 apple-design は Web 向け翻案のため、操作の即応性などを参考にし、CSS を移植しません。

結果: OS の更新・アクセシビリティ設定への追従を優先できます。一方、ネイティブ SDK と実機での確認が必要です。
検証: 独自 material と toolbarBackground の静的検査、iOS 26 でのバー／シート表示、システム設定別の確認。

## ADR-003: 意味トークンを一か所から生成

決定日: 2026-10-14 JST / 状態: 採用

`tokens.json` を色・寸法・共通モーションの正本とし、Swift 定数を生成します。
機能画面が直接色値、固定文字サイズ、角、余白、ガラス材質を追加することを検査で止めます。
コントラストは内容面の組合せを数式でテストします。

結果: 一括調整と差分レビューが可能になります。静的正規表現検査なので、すべての意味的逸脱を検出するものではありません。
検証: 生成差分、色の対称性、24 組のコントラスト、禁止例と許可例の回帰テスト。

## ADR-004: 範囲と情報種別が視覚的な軸

決定日: 2026-10-14 JST / 状態: 採用

単節、複数節、章またぎを同じ読書階層で扱い、選択全体と終端を表示します。
本文、要約、生成解説、資料を区別します。
モデル選択は設定へ置き、読書ヘッダーの主要操作にしません。

結果: 機能追加後も「どこを読んでいるか」を見失いにくくなります。
検証: UI / 状態テストと目視で、切替・質問・戻る・再試行後も同じ範囲であること。

## ADR-005: 装飾より読みやすさを優先

決定日: 2026-10-14 JST / 状態: 採用

意味のあるシステム文字スタイルを使い、本文の色コントラストを通常外観から確保します。
共通の内容面は不透明にします。
Reduce Motion では独自の状態アニメーションを止めます。
触覚は利用者が起こした選択と、確定した保存に限定します。

結果: 視覚表現だけでなく、文字拡大や VoiceOver の操作順でも読書の構造が伝わります。
検証: 数式で確認できる色と、実機でしか確認できない読上げ・操作・表示を別々に記録します。

## 例外の追加手順

1. 既存の部品では不足する具体的な操作または情報を記述します。
2. 対象画面、影響を受ける範囲、代替案、期限または削除条件を記述します。
3. この文書に次の ADR を追加し、検証手順を指定します。
4. `exceptions.json` に `file`、`rule`、`rationale`、`adr` を登録します。
5. 機能差分と同時にレビューします。ルール全体を無効化しません。

現在、許可した例外はありません。
