# q URL handoff and extension navigation — corrected conclusion

The previous copy-only decision conflated the existence of a ChatGPT question URL with one failing extension-opening API. It is superseded here. Release authorization was subsequently received for the integrated 0.1.18 candidate; publication evidence is recorded separately from this source description.

[The supplied Zenn article](https://zenn.dev/rsk31/articles/de35b75910c1dc) describes the q parameter and automatic answers. [The supplied Community thread](https://community.openai.com/t/query-parameters-in-chatgpt/1027747) reports both prefilled and automatically submitted behavior, with differences by login state and frontend. These are useful empirical reports, even though they are not a vendor API contract. No hints, model or temporary-chat parameter is added.

The candidate constructs https://chatgpt.com/ with a single q query item containing the same user-facing prompt as the clipboard path: current question, selected book/chapter/verse, reported translation and actual shared text. Encoding uses UTF-8 percent escapes with only the unreserved ASCII set left literal. Japanese, newlines, emoji and reserved symbols round-trip exactly; raw plus, ampersand and hash cannot become additional parameters or fragments. No account token, model settings, private conversation history or Gemma system prompt enters the builder.

Encoded URLs above 16 KiB are rejected by an explicit app interoperability policy; this is not represented as ChatGPT's server limit. The original prompt is never truncated. Full-text clipboard and protected main-app handoff remain available. The preview warns that URLs can persist in browser history and that opening may start an answer automatically. It does not promise a prefill-only flow.

A synthetic Japanese/newline/reserved-symbol/emoji q URL was opened in the existing logged-in Chrome environment. The complete question appeared in ChatGPT's input editor, the send button remained, and the query disappeared from the address bar. No send button was pressed. That environment therefore demonstrated prefill without automatic submission; it does not establish the same behavior for logged-out or native-app sessions.

The signed actual iOS26.0.1 Share Extension demonstrates a different result for the public SwiftUI openURL environment action than for NSExtensionContext.open. The latter returned false for both ChatGPT and an unrelated Apple HTTPS destination. A user tap invoking SwiftUI openURL opened Safari successfully with the q URL; its native regression case passed in 23.2 seconds. An initial test that expected failure was corrected, and its failing log was retained. This is not a private UIApplication/responder-chain workaround: UIApplication is never called from the extension. A normal SwiftUI Link is retained only in DEBUG/Simulator fixtures as a comparison probe.

For hosts that cannot open the URL, the preview also offers copying the URL or staging the prompt for the containing app's Settings. Staging is an explicit action. The protected, backup-excluded App Group payload expires after ten minutes, binds to the current local owner marker, is removed on account change/logout, and is never a shared server cache. Main-app open/copy revalidate both the owner and exact payload before acting. The app does not launch automatically; the user opens the containing app and explicitly taps the reviewed q link. Long payloads use full-text copying. Visibility preferences are separate from account and AI consent, with no empty composer gap when hidden.

The main-app Settings load is owned by the visible Form rather than an empty conditional child, so an initially absent handoff can appear after account restoration or foregrounding. Preview status is owned by its presented view so copy/staging feedback updates immediately. The Settings list uses a short preview and a full-text navigation view rather than placing a long body inline.

Swift core includes lossless URL, length, empty input, account mismatch and expiry tests. The full local validation suite passed with a real-path temporary directory; the earlier macOS symlink-temporary-directory refusal was not bypassed or weakened. Native case-level outcomes and screenshots, exact release source commit, CI, IPA/feed hashes and backend deployment status belong to the release provenance.

Physical-device crash diagnosis, real Gemma quality, native ChatGPT-app launch and the final SideStore installation on a physical phone remain unverified. Formal ChatGPT logo adoption remains incomplete; the UI uses the service name. PR 1's unmerged harness changes are excluded.
