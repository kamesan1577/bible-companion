# Native UI regression evidence

Run `make ios-ui` on a clean clone with the checked-in configuration. It creates and later removes its own dedicated Simulator by default; explicit `--device` must refer to a device reserved for this task. Separate clones keep DerivedData independent. UI builds use local ad-hoc Simulator signing so App Group-backed drafts/history are tested with their real entitlements; no personal identity or provisioning profile is used. The unsigned build gate remains separate. The containing app is installed after boot completion and before XCTest, including Share Extension registration. It uses the production native views through the existing `--simulator-qa` fixture entrypoint in Debug and invokes **both** XCTest schemes. The ordinary Debug visibility test checks that developer-only content does not leak into the user view. Production signing and actual remote service behavior are separate gates.

Find `.cache/harness/ios-ui-TIMESTAMP/ReadingInteractionUI.xcresult`, open it in Xcode, inspect failed assertions and all `keepAlways` attachments. Apple provides `xcrun xcresulttool export attachments --help` for command-line export (options vary with Xcode); keep exports ignored. Record the tested commit, Xcode/runtime/device, test names, screenshots reviewed and findings in the handoff. A screenshot file or accessibility assertion alone does not prove visual acceptance. Do not replace a baseline just because an image differs.

The existing tests exercise actual share extension presentation and repeated return, stored profiles and MapKit in the extension, early/late Acts identities and future-name suppression, candidate map provenance, Wikipedia/source navigation, reading pages, keyboard visibility, consent and recovery. The UI command allows 60 minutes for the complete current suite (98 test methods at the 0.1.23 integration), without changing assertions or retrying failures. The full suite also includes commentary rendering from multiple books. Tests must fail on failed assertions; the harness never automatically retries them. Map tiles may need Apple network access; missing tiles do not justify inventing geography or asserting visual success.

Before a distribution candidate is called device-accepted, inspect at least: first launch/import, YouVersion → share extension → return to app, people/place/source navigation, readable map and candidate uncertainty, keyboard/send, offline recovery, text size/accessibility, and light/dark mode. Use a real already-provisioned iPhone to verify App Group queue sharing, signed extension delivery, passkey browser return and SideStore re-signing. The simulator fixture cannot prove those. No new certificate, permission or account is created by this harness.

The screenshot fixture uses an available iPhone 17 Pro in the latest installed iOS runtime, independent of which peer device is booted. Model/runtime/owned UDID are logged. No new runtime is installed. `make ios-ui UI_CLASS=ArtworkCatalogUITests` (workflow `ui_suite=artwork`) is a targeted diagnostic only; the default full run remains the merge gate. See [the current contract migration](UI-CONTRACT-MIGRATION.md) for the original 32 failures and maintained coverage.
