# 0.1.1 preview source and IPA

The publication commit adds the native Swift 6 app, Share Extension, TypeScript backend, and existing tests to the previous workflow-only history. The release tag `v0.1.1-preview.1` remains at the earlier commit; use this document's publication commit for source checkout, not that tag.

`v0.1.1-preview.1-provenance.json` records the original IPA SHA-256, toolchain, and SHA-256 of every native source file. These native files were compared byte for byte with the local source used for the distributed IPA. Public backend configuration replaces personal account/database IDs with placeholders and sets the developer allowlist to empty. One-off administration scripts, credentials, signing profiles, device records, logs, and private configuration are excluded.

## Native build

On macOS with Xcode 26.0.1, iOS 26 SDK and XcodeGen 2.44.1:

```sh
sh apps/ios/Scripts/generate-project.sh
xcodebuild -project apps/ios/BibleCompanion.xcodeproj \
  -scheme BibleCompanion -configuration Release -sdk iphoneos \
  -derivedDataPath /tmp/bible-release \
  CODE_SIGNING_ALLOWED=NO \
  BIBLE_BUNDLE_ID=org.kamesan1577.BibleCompanion \
  BIBLE_APP_GROUP=group.org.kamesan1577.BibleCompanion \
  'BIBLE_API_URL=https:/$()/bible-companion.kamesan1577.workers.dev' build
```

The command builds both targets without an Apple signing account. For an isolated simulator build use `-sdk iphonesimulator -destination 'generic/platform=iOS Simulator'`, and omit the three endpoint/identifier overrides to use checked-in offline defaults.

The distributed package was made by copying `BibleCompanion.app` under `Payload/`, applying ad-hoc signatures to the Share Extension and then the containing app using the App Group entitlement from the checked-in entitlements files (with the concrete group above), verifying both signatures, then ZIP packaging `Payload/`. iloader or SideStore subsequently replaces those signatures with the user's development signing. No personal signing certificate or provisioning profile is distributed. Packaging is not claimed to reproduce the historical IPA byte for byte: timestamps, build paths and signatures can differ.

## Checks and limits

```sh
npm ci
npm run typecheck
npm test
npm run design:check
npm run infra:test
cd apps/ios
swift test
```

The release app was installed and launched on an iPhone using iloader. Device-side installation appended a development-team suffix to the bundle ID. Actual physical-device Share Extension interaction is pending user confirmation. Foundation package tests are distinct from iOS-hosted XCTest; the latter previously stalled locally and is not reported as passed. AI is disabled on the deployed backend and curated material coverage is partial.
